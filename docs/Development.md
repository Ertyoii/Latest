# Learning from Latest

Start with a behavior and trace it from the view to its owner and tests. The useful lessons are explicit ownership, bounded work, and observable behavior. The platform-specific update machinery is more specialized than a typical SwiftUI application.

## A reading order

1. **Values and identity:** [Version](../Latest/Domain/Version/Version.swift), [App](../Latest/Domain/App.swift), and [VersionTest](../Tests/Version/VersionTest.swift). Stored version identity and vendor update precedence are different operations. Precedence is directional and must not be used as a sorting relation. App metadata is immutable; reference identity lets a refreshed instance trigger presentation updates even when its app identifier stays the same.
2. **Composition:** [AppEnvironment](../Latest/App/AppEnvironment.swift) assembles services and feature state. [LatestApplication](../Latest/App/LatestApplication.swift) defines scenes. Dependencies such as `AppUpdating` and `ApplicationWorkspace` mark side-effect boundaries and let tests exercise commands without installing or opening real apps.
3. **Discovery and concurrency:** [UpdateCheckCoordinator](../Latest/Services/UpdateChecking/UpdateCheckCoordinator.swift) coordinates discovery and bounded child tasks. [AppDataStore](../Latest/Services/AppDiscovery/AppDataStore.swift) protects collection changes with a mutex and publishes complete snapshots. A generation check and the mutation it guards must be atomic, or a stale lookup can restore a removed app.
4. **Presentation:** [AppListSnapshot](../Latest/Features/Updates/AppListSnapshot.swift) categorizes and sorts once; search reuses that work. [UpdatesListViewModel](../Latest/Features/Updates/UpdatesListViewModel.swift) owns list actions and selection. Selection observation is scoped separately so arrows do not invalidate the entire list. Read [UpdatesScrollList](../Latest/Features/Updates/UpdatesScrollList.swift) alongside the input contracts in `Tests/Migration`.
5. **Loading and caching:** [ReleaseNotesProvider](../Latest/Services/ReleaseNotes/ReleaseNotesProvider.swift) owns source fallback and request lifetime. [ReleaseNotesPipeline](../Latest/Services/ReleaseNotes/ReleaseNotesPipeline.swift) validates and prepares one candidate. Semantic content is immutable; cache keys include source/version changes, and cancellation is never cached as a resource failure.
6. **Updating:** [UpdateQueue](../Latest/Services/Updating/UpdateQueue.swift) indexes operations by app identity. [SparkleUpdateOperation](../Latest/Platform/Sparkle/SparkleUpdateOperation.swift) keeps SDK state on the main actor and cancels pending download notifications before phase transitions. Download installers separately own validation, staging, replacement, and rollback.

## Design principles

- **Make call sites clear.** Swift's [API Design Guidelines](https://www.swift.org/documentation/api-design-guidelines/) prioritize clarity over brevity. Return an optional only when absence is possible. Introduce protocols at useful boundaries; avoid adding an abstraction for a hypothetical second implementation.
- **Keep state close to its owner.** Use view-local state for local interaction and pass explicit inputs to children. SwiftUI's [model-data guidance](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app) describes Observation and ownership. This app retains Combine snapshot feeds alongside narrowly observed selection; changing wrappers alone is not a performance improvement.
- **Choose an isolation boundary.** UI and SDK callbacks belong on the main actor; shared synchronous state needs a consistent lock. Actor methods can interleave at `await`. After suspension, check cancellation or request identity before committing a result. See the [Swift concurrency guide](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/concurrency/).
- **Keep work out of view evaluation.** Stable identifiers, prepared snapshots, bounded subscriptions, and cached formatting reduce repeated work. Apple's [SwiftUI performance session](https://developer.apple.com/videos/play/wwdc2023/10160/) explains dependency scope and row identity. Measure representative Release workloads before adding caches or changing collection algorithms.
- **Use native integrations deliberately.** The AppKit table, WebKit renderer, authenticated installer helper, and cache compatibility reader have concrete behavior contracts. Removing them requires equivalent input, accessibility, rendering, and installation behavior.
- **Test outcomes.** Tests should detect an incorrect selection, stale result, invalid package, wrong version, or broken command. Keep fixtures deterministic and preferences isolated. Table-driven cases suit version rules; async progress tests should exercise actual callbacks. Script tests use temporary directories and stub external commands so validation cannot kill apps or run Xcode.

## Making a change

Use the commands in the [README](../README.md). Start with the affected behavior tests, then run the background suite and formatting check. UI behavior needs the UI lane and same-host original/candidate captures. Performance claims need the same workload on the same hardware; a microbenchmark is evidence for its measured operation, not the whole application.

Experimental reports belong in `build/`. Keep failed visual, interaction, and performance gates visible. Sidebar selection uses AppKit's native source-list material because a semantic SwiftUI selection color does not reproduce it exactly. Input tests must finish synthetic clicks and let a newly assigned native responder settle before testing its key handlers. The high-refresh-rate performance targets remain unmet; passing appearance and focus contracts does not establish those performance results.
