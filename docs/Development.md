# Learning from Latest

Start with a behavior and trace it from the view to its owner and tests. The useful lessons are explicit ownership, bounded work, and observable behavior. The platform-specific update machinery is more specialized than a typical SwiftUI application.

## From launch to every feature

Read these steps in order. For each step, follow one call into its owner before moving on. The first eight steps cover the normal application; installation adapters come last because they have more platform constraints.

1. **Launch — [main.swift](../Latest/App/main.swift).** Top-level Swift code chooses the application entry point. `if` selects the test host or `LatestApplication.main()`. A private Boolean calculation detects hosted XCTest. The hosted test application avoids starting discovery and opening production windows. Unhosted function tests never execute this file.
2. **Scenes and ownership — [LatestApplication](../Latest/App/LatestApplication.swift) and [AppEnvironment](../Latest/App/AppEnvironment.swift).** A `struct` describes scenes; its `body` declares the main window, Settings, About, and Licenses. `@StateObject` retains the environment that assembles the app's services. `let` makes a dependency fixed after initialization; `var` holds changing state. `@MainActor` confines UI-facing work. The stateless release-menu action is an ordinary value, so it needs no observation wrapper. `start()` begins checking installed apps immediately while the notes catalog refreshes; `stop()` cancels startup work and observations.
3. **The window and controls — [LatestRootView](../Latest/App/LatestRootView.swift), [UpdatesSidebarView](../Latest/Features/Updates/UpdatesSidebarView.swift), and [UpdatesToolbar](../Latest/Features/Updates/UpdatesToolbar.swift).** SwiftUI composes child views and modifiers into a layout. The sidebar shows search and rows; the detail pane shows the selected app. `@ObservedObject` reads a model owned elsewhere. `@FocusState` handles keyboard focus. The toolbar observes checking progress and calls the reload command. About is icon/name/version/copyright; Licenses reads bundled notices.
4. **App values — [App](../Latest/Domain/App.swift), [Bundle](../Latest/Domain/Bundle.swift), [Update](../Latest/Domain/Update.swift), and [Version](../Latest/Domain/Version/Version.swift).** An immutable `App` combines installed metadata, an optional update result, and the ignored flag. `Optional` represents absence; `Result` represents success or failure. Enums model sources, notes, and update actions. App equality compares identity and version, while `===` checks whether two references are the same instance. Vendor version precedence is directional and must not be used as a sorting relation.
5. **Finding installed apps — [AppDirectoryStore](../Latest/Services/AppDiscovery/AppDirectoryStore.swift), [AppLibrary](../Latest/Services/AppDiscovery/AppLibrary.swift), and [BundleCollector](../Latest/Services/AppDiscovery/BundleCollector.swift).** The directory store supplies default and user-added locations. Library observations collect filesystem changes into complete scans. Bundle collection reads identifiers, versions, receipts, and updater metadata. Obsidian and Delta have specialized installed-version readers. `AppDataStore` protects collection mutations with a mutex and publishes discovery, incremental results, and the current scan generation together. `AppListSnapshot` retains row order under a neutral Installed Apps heading during checks, then applies the usual sections and date sorting on completion.
6. **Checking versions — [UpdateCheckCoordinator](../Latest/Services/UpdateChecking/UpdateCheckCoordinator.swift) and [UpdateCheckingService](../Latest/Services/UpdateChecking/UpdateCheckingService.swift).** `async` functions can suspend; `await` marks the suspension; `throws` carries failures. The coordinator chooses App Store, Sparkle, or Homebrew checks and bounds child tasks. A generation check and its guarded mutation are atomic, so an older result cannot restore a removed app. The service publishes progress. App Store lookups and catalog loads share pending work; cancelling one lookup reader releases that reader while other readers can keep using the fetch. An explicit refresh invalidates App Store lookup metadata.
7. **Sorting, searching, selection, and row actions — [AppListSnapshot](../Latest/Features/Updates/AppListSnapshot.swift), [UpdatesListViewModel](../Latest/Features/Updates/UpdatesListViewModel.swift), and [UpdatesScrollList](../Latest/Features/Updates/UpdatesScrollList.swift).** Snapshots categorize and sort once; search refilters those prepared sections. Dictionaries provide identity and row-index lookup. `LazyVStack` materializes rows as needed and pins section headers. Narrow Observation state updates selection colors without rebuilding the whole list. Keyboard navigation uses prepared geometry. Open, Reveal in Finder, Ignore, and Update call explicit service boundaries. Cached icons and date/version strings avoid repeated row work.
8. **Settings and commands — [SettingsViewModel](../Latest/Features/Settings/SettingsViewModel.swift), [SettingsRootView](../Latest/Features/Settings/SettingsRootView.swift), and [AppCommands](../Latest/App/AppCommands.swift).** `Binding` connects a control to a getter and setter. `@AppStorage` persists appearance; the injected preferences own visibility and sorting. Locations adds/removes allowed directories and clears a removed selection. The helper banner reports availability and registration errors. Commands reuse feature actions for search focus, checking, bulk updates, opening/revealing selection, display options, and external project/release links. The workspace protocol makes those side effects testable.
9. **Release notes — [ReleaseNotesDetailViewModel](../Latest/Features/ReleaseNotes/ReleaseNotesDetailViewModel.swift), [ReleaseNotesProvider](../Latest/Services/ReleaseNotes/ReleaseNotesProvider.swift), and [ReleaseNotesPipeline](../Latest/Services/ReleaseNotes/ReleaseNotesPipeline.swift).** The header updates immediately; keyboard selection waits briefly before loading notes. A delayed loading state avoids flashes for cached content. Request identifiers suppress older completions. The provider tries app metadata and catalog fallbacks, targeting the available or installed version. The pipeline checks app/platform/version and prepares immutable semantic content. Actor caches serialize shared state; persistent cache keys include source/version changes. WebKit handles dynamic sources and selectable rendering. Extraction checks request identity and cancellation after suspension, finishes once, and releases its resources.
10. **Updating and recovery — [AppUpdating](../Latest/Services/Updating/AppUpdating.swift), [UpdateQueue](../Latest/Services/Updating/UpdateQueue.swift), and [UpdateActionView](../Latest/Features/ReleaseNotes/UpdateActionView.swift).** Protocols describe the capability a feature needs; `any AppUpdating` accepts an implementation. The queue deduplicates by installed-app identity and limits concurrent operations. Enums describe pending/download/extraction/install/error states. Rows and detail actions observe per-app streams. Update All prepares the helper only for native App Store actions, opens the Store once for external/manual actions, and skips queued updates. Individual App Store actions also check the current manual preference. Retry and Cancel follow the operation's phase; installation cannot be interrupted after its commit boundary.
11. **Platform adapters — [SparkleUpdateOperation](../Latest/Platform/Sparkle/SparkleUpdateOperation.swift), [AppStoreUpdateOperation](../Latest/Platform/AppStore/AppStoreUpdateOperation.swift), and [AppDownloadUpdateOperation](../Latest/Platform/Download/AppDownloadUpdateOperation.swift).** Sparkle manages its SDK lifecycle and supports another quit request. CommerceKit downloads native App Store updates; the signed helper repairs the specific PackageKit entitlement failure. Wrapped iOS apps use the Store. Standalone installers fetch fresh metadata, check checksums/signing/architecture/OS, stage on the destination volume, confirm quitting, and keep a recoverable original until replacement succeeds. Obsidian payload updates verify the vendor signature. These adapters are advanced integration examples; study them after the value, state, and concurrency code.
12. **Tests as executable examples — [Tests](../Tests).** Start with `VersionTest`, `AppListSnapshotTest`, `AppDependencyBoundaryTest`, `ReleaseNotesDetailViewModelTest`, and `AppUpdatingBoundaryTest`. They demonstrate version rules, ordering, injected dependencies, stale-result rejection, and lifecycle behavior without installing applications. The default `Latest Unit Tests` scheme runs domain, snapshot, presentation, and executor tests without an application. `--integration` adds background app-hosted platform, offscreen layout, and WebKit contracts. Window/input/visual tests and live vendor/helper checks use their documented opt-in lanes.

The App Store adapter embeds declarations under `Frameworks/`; it does not depend on the mas executable. The signatures used by the updater were compared with [mas-cli revision 6c5032d](https://github.com/mas-cli/mas/tree/6c5032dc8da74668c407b76d02463eea20b732a5/Sources/PrivateFrameworks/include), extracted from macOS 26.5. Observer registration returns a string token, and download metadata, status phases, purchase responses, and response downloads may be absent. The purchase completion uses `_Nullable_result` so Swift's async importer preserves a missing response. Newer upstream declarations include unverified types; review the APIs actually used instead of copying the complete private framework surface. Background tests cover token registration/removal and the nullable callback bridge without initiating downloads.

A useful first exercise is to follow a search edit: the field changes `searchQuery`, the view model refilters a snapshot, and SwiftUI receives the visible sections. Then trace an Update click: the view model calls `AppUpdating`, the source-provided action schedules an operation, and a state stream changes the button's presentation. Both traces separate presentation, pure data work, and platform side effects.

## Design principles

- **Make call sites clear.** Swift's [API Design Guidelines](https://www.swift.org/documentation/api-design-guidelines/) prioritize clarity over brevity. Return an optional only when absence is possible. Introduce protocols at useful boundaries; avoid adding an abstraction for a hypothetical second implementation.
- **Keep state close to its owner.** Use view-local state for local interaction and pass explicit inputs to children. SwiftUI's [model-data guidance](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app) describes Observation and ownership. This app retains Combine snapshot feeds alongside narrowly observed selection; changing wrappers alone is not a performance improvement.
- **Choose an isolation boundary.** UI and SDK callbacks belong on the main actor; shared synchronous state needs a consistent lock. Actor methods can interleave at `await`. After suspension, check cancellation or request identity before committing a result. See the [Swift concurrency guide](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/concurrency/).
- **Keep work out of view evaluation.** Stable identifiers, prepared snapshots, bounded subscriptions, and cached formatting reduce repeated work. Apple's [SwiftUI performance session](https://developer.apple.com/videos/play/wwdc2023/10160/) explains dependency scope and row identity. Measure representative Release workloads before adding caches or changing collection algorithms.
- **Use native integrations deliberately.** The Settings locations table, scroll configuration bridge, WebKit renderer, authenticated installer helper, and cache compatibility reader have concrete behavior contracts. Removing them requires equivalent input, accessibility, rendering, and installation behavior.
- **Test outcomes.** Tests should detect an incorrect selection, stale result, invalid package, wrong version, or broken command. Keep fixtures deterministic and preferences isolated. Table-driven cases suit version rules; async progress tests should exercise actual callbacks. Script tests use temporary directories and stub external commands so validation cannot kill apps or run Xcode.

## Making a change

Use the commands in the [README](../README.md). Start with the affected behavior tests, then run the background suite, formatting check, and correctness lint. Declaration analysis is advisory: review runtime and conditional callers before deleting a candidate. UI behavior needs the UI lane and same-host original/candidate captures with fixed window geometry, inactive state, and backdrop. Performance claims need the same workload on the same hardware; a microbenchmark is evidence for its measured operation, not the whole application.

Experimental reports belong in `build/`. Report behavior regressions and measurement limits. macOS 26 and 27 share SwiftUI sidebar layout, selection, and actions. A narrow AppKit bridge configures overlay indicators and nonelastic scrolling. Input tests must finish synthetic clicks and let a newly assigned native responder settle before testing its key handlers.
